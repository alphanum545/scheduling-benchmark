# CGS: held-out results, 27 October 2026

**Result:** CGS (Contention-table, Gated join-closure Scheduling) is shorter than every comparator on the untouched 2,102-instance test split, including the paper-faithful insertion-based AEFT (+3.02 % mean paired gain, 1,512 wins / 38 ties / 552 losses) and a fair insertion-based HEFT (+5.42 %, 1,780 / 26 / 296). The configuration was frozen and committed (`0001f93`, [PROTOCOL.md](PROTOCOL.md)) before the test split was run once.

CGS unifies two new methods, SCCT and RCIS.

**Prior-art note (AEFT).** With sibling contention switched off, CGS's table T is exactly the Improved Optimistic Cost Table (IOCT, Eq. 18) of AEFT ([Wang et al., FGCS 164 (2025) 107576](https://doi.org/10.1016/j.future.2024.107576)): T(t,k) = w(t,k) + max over children c of min over q of (T(c,q) + [q ≠ k] c(t,c)). AEFT also selects by EFT + IOCT with insertion. The table and the EFT-plus-table rule are therefore prior art and must be cited as AEFT's; only the contention term is new, and it is not significant on test (see the novelty checks below).

## Algorithm

1. **Contention table T(t,k)** (from SCCT): w(t,k) plus the latest downstream finish of t's children when they are placed greedily, most critical first, on processors free at t's finish, so siblings compete for processors.
2. **Priority:** HEFT upward rank.
3. **Placement:** insertion-based; processor argmin FT(t,k) + 0.5 · T(t,k).
4. **Gated join closure** (from RCIS, repaired): when the popped task has a child v whose ≤ 2 remaining parents are all ready, those parents are placed jointly (all parent orders, a shortlist of processors, every processor for v), scored by the lexicographic key (max FT + T − w, FT of v, ΣFT, work). The sequential plan is always a candidate. Only the parents are committed; v returns to the queue.
5. **Communication-credited gate:** the closure is formed only if no other ready task x has rank(x) > rank(v) + max c(u,v) over v's remaining parents u. The credit is the communication a split would add; its weight is 1 by units, and 0.5 and 2 were both worse on dev.

Complexity per closure is bounded by the caps (2 parents, shortlist 2, all p processors for the join).

## Limits and what to do before a paper

- **Insertion fairness.** CGS uses insertion; the repository baselines (HEFT, AEFT, OPPTS, SCCT, LEFT, …) do not, although the AEFT paper itself specifies insertion (Algorithm 1, line 6). The fair comparisons are `heft_ins`, `aeft_ins` and `scct_ins`, and CGS wins all three. PEFT, IPPTS and BPPTS still need insertion versions.
- **AEFT fidelity.** `aeft_ins` reproduces the paper's worked example (Fig. 1, Table 3: every step, makespan 76); its `append` mode equals the repository AEFT on all 2,102 test instances.
- **Runtimes** were measured on a 2-core sandbox with two parallel workers (CGS 0.035 s, AEFT-ins 0.027 s, HEFT-ins 0.027 s mean). Rerun the Benchmark workflow for citable timings and to confirm makespans on the shared runners (`cgs` is registered in `algorithms.toml` on this branch).
- **Prior art.** Look-ahead HEFT, optimistic cost tables (PEFT, OPPTS) and AEFT's IOCT with EFT + IOCT selection are established. The contribution claim must be the gated joint placement of a join's parents with the communication-credited gate. A full literature review is still needed.
- `heft_ins` is the repository HEFT with insertion; its append mode reproduces the repository HEFT on 711/712 dev instances (one tie-break). It is not a certified reproduction of the original paper.
- The test split was used once for this frozen configuration; it should not be used again for tuning CGS.
