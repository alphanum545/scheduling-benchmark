# CGS: held-out results, 27 October 2026

**Result:** CGS (Contention-table, Gated join-closure Scheduling) is shorter than every scheduler in the repository on the untouched 2,102-instance test split, including DSLA (+1.45 % mean paired gain, 1,293 wins / 72 ties / 737 losses) and a fair insertion-based HEFT (+5.42 %, 1,780 / 26 / 296). The configuration was frozen and committed (`0001f93`, [PROTOCOL.md](PROTOCOL.md)) before the test split was run once.

CGS unifies the two new non-DSLA methods, SCCT and RCIS. It does not call or reuse DSLA, whose code and ideas (state-aware child look-ahead, dual policy, EFT/look-ahead blend) are not part of it; DSLA appears only as a comparator.

## Algorithm

1. **Contention table T(t,k)** (from SCCT): w(t,k) plus the latest downstream finish of t's children when they are placed greedily, most critical first, on processors free at t's finish, so siblings compete for processors.
2. **Priority:** HEFT upward rank.
3. **Placement:** insertion-based; processor argmin FT(t,k) + 0.5 · T(t,k).
4. **Gated join closure** (from RCIS, repaired): when the popped task has a child v whose ≤ 2 remaining parents are all ready, those parents are placed jointly (all parent orders, a shortlist of processors, every processor for v), scored by the lexicographic key (max FT + T − w, FT of v, ΣFT, work). The sequential plan is always a candidate. Only the parents are committed; v returns to the queue.
5. **Communication-credited gate:** the closure is formed only if no other ready task x has rank(x) > rank(v) + max c(u,v) over v's remaining parents u. The credit is the communication a split would add; its weight is 1 by units, and 0.5 and 2 were both worse on dev.

Complexity per closure is bounded by the caps (2 parents, shortlist 2, all p processors for the join).

## Why each part is there (development split, 712 instances)

| Step | Change | Gain vs insertion HEFT |
|:--|:--|--:|
| repository SCCT | non-insertion | −0.74 % |
| + insertion | `scct_ins` | +3.70 % |
| + HEFT rank, selection weight 0.5 | `cgs single` | +4.74 % |
| + gated joint closures (plain rank gate) | `cgs credit=0` | +5.32 % |
| + communication credit in the gate | **`cgs`** | **+5.52 %** |

Ungated closures fall to +1.24 % (they help only at CCR 10). Sibling contention in T adds +0.2 % within `cgs single` (not significant on dev, p = 0.86); most of the table's value is the downstream estimate itself. The SCCT priority table was no better than HEFT's rank once insertion was added. All dev measurements: `results/dev_results.csv`, summaries `results/dev_*.txt`.

## Limits and what to do before a paper

- **Insertion fairness.** CGS uses insertion; DSLA and all repository baselines (HEFT, OPPTS, SCCT, LEFT, …) do not. CGS's comparisons against `heft_ins` and `scct_ins` are the fair ones, and it wins both. Its margin over DSLA may shrink if DSLA were given insertion; that is a fair question a reviewer could ask.
- **Runtimes** were measured on a 2-core sandbox with two parallel workers (CGS 0.035 s, DSLA 0.032 s, HEFT-ins 0.027 s mean). Rerun the Benchmark workflow for citable timings and to confirm makespans on the shared runners (`cgs` is registered in `algorithms.toml` on this branch).
- **Prior art.** Look-ahead variants of HEFT and optimistic cost tables (PEFT, OPPTS) are established; the contribution claim must be the sibling-contention table combined with gated joint placement of a join's parents and the communication-credited gate. A full literature review is still needed.
- `heft_ins` is the repository HEFT with insertion; its append mode reproduces the repository HEFT on 711/712 dev instances (one tie-break). It is not a certified reproduction of the original paper.
- The test split was used once for this frozen configuration; it should not be used again for tuning CGS.
