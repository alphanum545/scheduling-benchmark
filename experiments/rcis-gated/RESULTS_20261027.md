# RCIS commitment timing: development results, 27 October 2026

**Decision:** the RCIS joint-closure loss is explained by *when* closures are committed, and a priority gate repairs it. The repaired variant, `rcis_gated`, beats its own single-task ablation by **+2.02 %** mean paired gain on the development split. It is still **not competitive** with the strongest baselines overall (HEFT −0.45 %, OPPTS −1.60 %, SCCT −2.62 %, DSLA −7.40 %), so it is not a final paper algorithm. No test-split runs were made.

Builds directly on `research/rcis-standalone-20261026` (see `experiments/rcis-standalone/RESULTS_20261027.md`). Like RCIS, nothing here calls DSLA, SCCT or BCR; those appear only as comparators.

## Hypothesis tested

The previous write-up proposed that immediate closure "consumes processor capacity too early and harms independent ready tasks". In `rcis.cpp`, popping task *u* commits *u*, its sibling parents and the join at once, even when other ready tasks have higher priority (critical-path rank *h*). Each such out-of-order commitment is counted as an **inversion**.

## Method

`rcis_gated.cpp` is `rcis.cpp` plus three options; with default flags it is RCIS unchanged.

| Flag | Meaning |
|:--|:--|
| `--commit=0` (default) | commit every task of the chosen closure plan |
| `--commit=1` | commit the parents only; the join returns to the priority queue |
| `--commit=2` | commit only the popped task, on the processor the closure plan chose |
| `--gate=1` | form a closure only if no outside ready task outranks the lowest-ranked closure parent |
| `--gate=2` | form a closure only if no outside ready task outranks the join |
| `--fallback` | when the gate rejects a closure, still use it as lookahead for the popped task |

`rcis_gated` = `--gate=2 --commit=1`: join-aware parent placement, used only when the join is already next in priority.

**Execution.** Run locally, not via the Actions workflow: `run.py` compiles each variant, runs it on all 712 development instances (same `split_of` hash as `tools/bench.py`, same datasets rebuilt with `tools/fetch_data.py`), and checks every schedule with `tools/evaluate.cpp check`. Reproduction check: locally measured makespans for `rcis`, `rcis_single`, `dsla`, `scct`, `heft`, `oppts`, `left` match `results/reports/rcis-dev-complete-v1/results.csv` on **712/712** instances each. `rcis_gated.cpp` with default flags and with `--single` matches `rcis` and `rcis_single` on 712/712. Every run in this study produced a valid schedule.

## Results versus the single-task ablation (all 712 dev instances)

Mean paired gain = mean over instances of `100 * (single − variant) / single`; positive favours the variant. *p* is a two-sided paired Wilcoxon test, **not** Holm-corrected and **not** grouped by DAG; treat as exploratory. Full table: `results/vs_single.txt`.

| Variant | Mean makespan | Gain vs single (%) | W / T / L | *p* |
|:--|--:|--:|:--|--:|
| rcis (original) | 4698.88 | −1.395 | 254 / 8 / 450 | 4.9e-26 |
| gate 1 | 4680.22 | −0.987 | 269 / 10 / 433 | 7.5e-20 |
| gate 2 + fallback | 4655.94 | −0.134 | 296 / 8 / 408 | 7.3e-15 |
| commit parents only | 4655.59 | +0.764 | 323 / 8 / 381 | 8.1e-10 |
| commit head only | 4648.12 | +0.865 | 339 / 11 / 362 | 2.0e-07 |
| gate 1 + parents only | 4614.85 | +1.271 | 346 / 19 / 347 | 3.7e-04 |
| gate 2 | 4531.59 | +1.087 | 344 / 160 / 208 | 3.3e-09 |
| **gate 2 + parents only (`rcis_gated`)** | **4525.81** | **+2.022** | **388 / 134 / 190** | **7.8e-19** |
| rcis_single (reference) | 4545.55 | 0 | — | — |

Widening the closure search does not help: gate 2 with `--parents=3` gives +1.085 %, with `--shortlist=3` an identical result to gate 2. `rcis_gated` versus original RCIS: +2.49 %, 491 / 14 / 207, *p* = 1.2e-43.

Eleven variants were tried on the same development split and the best was picked, so +2.02 % carries selection bias and needs confirmation on unseen data.

## Mechanism evidence

From `trace.py` (RCIS stderr counters on all 712 instances):

- Original RCIS commits 123,110 closures and makes 131,360 inversions (1.07 per closure).
- Splitting instances into thirds by inversions per closure, RCIS's mean gain over single-task is **+2.49 %** in the lowest third (95/237 losses), **−2.74 %** in the middle (142/237) and **−3.93 %** in the highest (213/238). Spearman ρ = −0.31, *p* = 1.4e-17.
- Under `rcis_gated`, gate 2 rejects 177,318 closure opportunities and keeps 7,913 (about 4 %).

Every variant that commits less, or commits only when priority allows, removes the original loss. That supports the timing hypothesis. It does not show that every joint-closure design must fail.

## Limits

- Development split only; variant selection on the same split.
- Wilcoxon *p*-values are unadjusted and ungrouped; filename DAG grouping as in earlier reports was not redone.
- Runtimes were measured on a 2-core sandbox with two parallel workers; use them only for relative comparisons within this run. `rcis_gated` adds about 7 % mean runtime over single-task here.
- Baseline fidelity caveats from earlier reports still apply.

## Suggested next step

The gate fixes the joint mechanism, but the remaining gap is in the base scheduler: single-task RCIS already trails HEFT/OPPTS on the workflow families. Improving the priority (e.g. mean or OPPTS-style costs instead of minimum costs) is the larger lever, and the gate should be re-measured on top of it. Before any test-split use, register `rcis_gated` in the Actions benchmark (already added to `algorithms.toml` on this branch) to confirm the local numbers on the shared runners.
